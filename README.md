# Bionic Pocket

Версия 0.1.10: кнопка 📎 рядом с полем сообщения открывает системный выбор
файла. До 5 файлов по 10 MiB на сообщение; выбранные файлы можно убрать перед
отправкой. Черновики вложений принадлежат своему разговору. Передача идёт
частями с восстановлением позиции, прежними UUID и проверкой SHA-256.
Оригиналы сохраняются у выбранного помощника, имена видны в истории.
Текстовые файлы передаются модели как ограниченные фрагменты данных, остальные
файлы сохраняются в исходном виде. Автоматическое распознавание картинок,
PDF и архивов не заявляется. Для работы требуется обновлённый мост.

Версия 0.1.9: в списке разговоров кнопка `⋮` открывает архивирование,
восстановление и удаление с подтверждением. Кнопка `Archive` показывает архив.
Архив сохраняет историю и получение незавершённых ответов. Удаление убирает
только разговор с телефона; задания на ПК продолжают выполняться.
Ошибка подключения теперь показывает причину в строке состояния.

PC 120: выбор Гонца и Домового, отдельные разговоры и очереди
ответов. В настройках задаются два адреса и один общий токен. Для Гонца нужен
HTTPS. Домовой доступен только в офисной LAN; по явному решению владельца
допускается HTTP с передачей токена без шифрования. Адрес Домового должен
разрешаться только в частные адреса RFC1918/IPv6 ULA. Переадресация запрещена.
Сохранённый запрос закрепляется за исходным помощником и адресом; смена
помощника или настроек не пересылает его другому серверу.

На каждом ПК предусмотрены два канала: координатор Codex и телефон. Они
используют отдельные зарегистрированные рабочие копии, два слота задач и одну
последовательную очередь генерации. Два канала не требуют двух моделей.
Принятие задания, выполнение, доставка отчёта и проверка изменений — отдельные
статусы. Неопределённый результат отправки кодовой задачи требует проверки
координатором; автоматический повтор не создаёт дубликат.

Версия0.1.7: подтверждения и итоги Codex возвращаются в исходный разговор
отдельной карточкой, включая ранее завершённые запросы. Карточка обновляется
без дублей. Проверка выполняется при открытом приложении и не вызывает модель.

Мост предоставляет реальные статусы, дату, RAM и консоль PowerShell/RTK,

Доставка в Codex подтверждается только после фактической передачи; она не
означает выполнения задачи. Постоянный inbox проверяется каждые пять минут.

ошибках сервера. Проверки исполняют реальные Java-методы доставки с сетевыми
сбоями и HTTP404/429/5xx/401/403; отдельно проверяются Android-сборка и подпись.

Версия0.1.2: ответы отображают Markdown — заголовки, жирный/курсив, списки,
цитаты, ссылки, таблицы и блоки кода с отдельным копированием. HTML остаётся
обычным текстом. Интернет-поиск и чтение публичных страниц доступны и в обычном
чате через обновлённый мост; ответы содержат реальные ссылки. Провайдер поиска

ошибку, а не выдумывает результаты.

Лёгкий Android-клиент для своего Bionic: переписка с телефона, локальная история,
выбор проекта и задания с явным списком файлов. Без платного облачного API.

## Установка

Скачайте **BionicPocket.apk** из [последнего выпуска](https://github.com/OLDest/bionic-pocket/releases/latest).
Android 8.0 или новее. Разрешите установку APK браузеру, из которого скачали файл.
Откройте приложение → «Настроить сервер и токен»:

- Гонец: ваш HTTPS-адрес моста, например `https://assistant.example.org:1236`.
- Домовой: офисный адрес моста, например `http://192.168.88.1:1236`.
- Токен: Bearer-токен из локального config.json моста. Не добавляйте слово Bearer.

Нажмите «Сохранить». Токен шифруется ключом Android Keystore; резервное копирование
данных приложения отключено. В приложении нет рекламы, аналитики и сторонней
авторизации. История остаётся в приватном хранилище приложения на телефоне.

## Общение

«Общение» — обычный разговор с локальной моделью. Переписка сохраняется между
запусками; в запрос включается ограниченная недавняя история. При включённом управлении
мост предоставляет консоль по явному запросу пользователя под текущей учётной
записью Windows. Внешние программы выполняются через RTK; повышение прав
зависит от Windows/UAC. Например: «Выполни: Get-Location». Удалённый ответ сохраняется мостом: если
свернуть приложение или потерять сеть, результат забирается при возвращении.
Кнопка ☰ открывает разговоры и настройки; ＋ создаёт новый разговор. Долгое
нажатие на ответ копирует его. Ошибки можно повторить без дублирования запроса.

«Задача с файлами» — выбрать зарегистрированный проект, перечислить относительные
пути файлов через запятую или с новой строки и описать задачу. По умолчанию
включён только анализ. Изменения требуют снятия флажка и отдельного подтверждения.
Работа идёт в отдельной копии проекта; результат возвращается в этот же разговор.
Проверка и слияние в main выполняются отдельно. Если рабочая копия занята или
ожидает проверки предыдущей задачи, мост покажет причину и не запустит дубль.
Shell исполнителя работает от учётной записи ПК: список файлов задаёт scope,
но не является системной песочницей shell.

## Обновления

Приложение проверяет последний GitHub Release при открытии, не чаще раза в сутки.
Есть ручная проверка в настройках. Оно предлагает скачать новую версию, проверяет
SHA-256, размер, package ID, увеличение версии и совпадение подписи APK с уже
установленным приложением. Установку подтверждает системный установщик Android.
Без root нельзя незаметно устанавливать обновления обычного приложения.

## Сборка и выпуск

Требуются Python 3, Node 20+, JDK 17, Android SDK platform/build-tools 35 и RTK.
Укажите `JAVA_HOME`, `ANDROID_HOME`, `RTK`; локально build.py также находит SDK/JDK
рядом с YaGo. Под Windows все внешние команды build.py выполняются через RTK.

```
rtk proxy node --test server/mobile.test.mjs
rtk proxy py -3 build.py
```

Для существующего приложения задайте `BIONIC_SIGNING_DIR` с прежними
`release.keystore` и `keystore-password.txt`: при отсутствии ключа в явно заданном
каталоге сборка остановится. При первой сборке без такого каталога
сборка генерирует отдельный release-ключ в `.local/release.keystore`. Сохраните
его и `.local/keystore-password.txt` отдельно: следующий выпуск должен быть
подписан тем же ключом. Ключи, токены, APK и данные чатов исключены из Git.
Для личного APK создайте `.local/personal.json` с полями server/token и
запустите `build.py --personal`. При первом запуске настройки импортируются
в Android Keystore, если токен ещё не задан. Личный APK сохраняется только в
`.local/BionicPocket-personal.apk`; github_release.py запрещает его публикацию.
Последующие обновления приложения сохраняют подключение.
Для выпуска увеличьте version.json и версии в AndroidManifest.xml, выполните
сборку, commit/push и `rtk proxy py -3 github_release.py release`. Публикация
использует уже настроенный Git Credential Manager; токен не печатается.

## Мобильный API

`server/mobile.mjs` подключается к существующему авторизованному локальному
мосту после проверки Bearer и Origin. `/mobile/config` возвращает проекты;
`POST /mobile/messages` принимает requestId/chatId/text/mode/history и сразу
возвращает202. `/mobile/jobs/{id}` возвращает сохранённый ответ. Повторная отправка
того же requestId не создаёт вторую работу. Произвольные system/tool-роли в
истории запрещены. Рабочие задачи проходят обычную регистрацию scope/route/lease
моста. Мобильный клиент не подтверждает отчёты за ChatGPT и не снимает блокировки.

Сервер модели и ПК должны быть включены. Фоновый таймер Codex приложению не нужен.

Мост runtime6 поддерживает два активных задания: ChatGPT и телефон используют
разные рабочие копии YaGo. Обычный чат телефона принимается, пока работает
координатор. При заполнении обоих слотов новый обычный чат получает429; файловые
задачи имеют ограниченную очередь и сохраняют блокировку рабочей копии до ревью.
Генерации4B идут последовательно — это не обещание удвоенной скорости. Приложение
0.1.1 совместимо с этой настройкой без переустановки.

## Проверки первого выпуска

Сборка Java/DEX/APK и подпись проверяются инструментами Android SDK. Node-тесты
проверяют асинхронный ответ, восстановление, повторы, ограничения ввода, конфликт
занятого исполнителя, scope задач и результаты. Подключённого Android-устройства
во время разработки нет; фактическая установка и экран проверяются пользователем.

## Управление и передача в Codex

Примеры: «Статус задач», «Какой сегодня день?», «Покажи правила»,
«Запомни правило: …», «Передай в Codex: …», «Проверь сайт https://example.org».
Очередь и подтверждённая доставка показаны раздельно. Статусы читаются из
метаданных задач и команд; свободная GPU-память не угадывается. Правила
сохраняются между разговорами на сервере. Поисковое описание и прочитанная
страница различаются. Настройки API включаются владельцем моста:
mobileControlEnabled, mobileHostShellEnabled, shellEnabled, mobileStrictSources.
Секреты и runtime-config в репозиторий не включаются.
